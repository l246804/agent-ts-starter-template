# 目标项目继承"文档、决策与执行纪律"五条规则

本仓库把 DSH 调研（`docs/research/deepseek-harness-agent-architecture.md`）里可搬运的部分收敛成五条规则，并**发货到目标项目**：一条事实一个家（`C42`）、决策记录保留被拒替代并随现实更新（`C43`）、会漂移的事实写明复查条件（`C44`）、被拦下时的升级纪律（`C45`）、陷阱准入判据（`C46`）。

- **为什么发货**：目标项目拿到的四份文档此前只有**指针**，没有"事实住哪"的规则；防御条文也只覆盖"不为想象写防御"，不覆盖"被环境拦下时怎么办"。五条都属于"默认行为会走错"的那一类：默认是把新事实塞进最常读的文件（于是漂移）、只记结论不记被否掉的替代（于是反复重提）、把过期事实当当前事实（静默）、被拦下时绕过去（假绿或绕过失败的测试）。
- **发货形态**：前三条进 `AGENTS.md` 新的 `### Documents and decisions` 段（无条件、全形态），`C45` 追加到 `### Toolchain` 段，`C46` 进 `docs/agent-notes.md` 的框架段；每条由 `e2e/coverage.mjs` 声明一条发货行，两个方向都被 `assert.mjs` 逐 profile 审计。
- **仓库侧对应物**：`C44` 的仓库侧入口是 `docs/upstream-drift.md`（上游漂移时重验什么）；本仓库自身的决策记录纪律就是本目录的 ADR 系列（保留 `## Considered Options`，已实现的决策随现实更新事实）。

## Considered Options

- **只在 `GUIDE.md` 的散文里写"四份文档各有一个职责"** — 拒绝：指南的自述不会被目标项目的未来 agent 读到；它们读的是产物的 `AGENTS.md`，那里此前只有一行指针（`GUIDE.md:3145`）。
- **把五条并进已装的 mattpocock skills**（`writing-for-agents`、`domain-modeling`）— 拒绝：技能是**可发现**的，不是**已读**的；而且"被拦下时怎么升级"与"陷阱准入判据"在技能里没有对应物。重复搬运技能已覆盖的内容才是 no-op，这五条不是。
- **给目标项目补第 5 份继承 ADR 承载理由** — 暂缓：五条的"为什么"各一句话即可写进 bullet；代价是多一份要落位、要断言、要维护的文档。需要时按 `C42` 的落位规则补。
- **为新规则加机械门禁** — 拒绝：五条是文档与行为纪律，目标项目无法"违反"到能被断言的程度；唯一的机械保证是 coverage 门禁证明它们**确实按形态发货、且没有未认领的文本**。加假断言会造成"看起来有闸"的假绿，正是这几条自己要防的形态。
- **把"每条规则说得出谁判它红"（原候选 `C43`）也发货** — 拒绝（本轮）：它是元规则，收益随规则数量增长，而目标项目的规则集是固定的四十余条；它更像维护本仓库清单时用的纪律。

## Consequences

- 目标项目 `AGENTS.md` 净增 4 条 bullet（`### Documents and decisions` 三条 + `### Toolchain` 一条），`docs/agent-notes.md` 增一段，`docs/provenance.md` 增一张"上游移动时重验什么"的表。
- 条目空间从 80 个 id 增到 86（新增 `C42..C46` 与 `ADR-0013`），发货行同步 +5；`--self-check` 与逐 profile 审计同时约束它们，所以"漏发一条"与"多写一句无人认领的话"都会红。
- 全矩阵（9 个 profile）必须重跑一次，`docs/verification.md` 由 `e2e/record.mjs` 重写；这是本变更唯一的端到端证据。
