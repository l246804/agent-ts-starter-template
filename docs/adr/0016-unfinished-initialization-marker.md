# 未完成的初始化要能自证；不支持就地续跑

一次初始化在任何一步停下，目录里留下的东西**代码侧可能全绿**（实测：删掉 `docs/provenance.md` 与 `docs/adr/` 之后 `vp check` 仍然 pass）。指南自己的验证段能识别它——交付物断言在验证段最前，会报 `docs/provenance.md is missing — Phase 5 wrote no record`——但没有任何东西让**目录自己**说出来。本决策给目录一个自我陈述：`bootstrap` 写 `.guide-incomplete`，只有验证段全绿时才由它删除。

- **标记的语义是「这次运行没有以一次通过的验证收尾」**，不是「运行到哪一步」。所以删除动作必须在验证段的最后（`done_checking` 之前）：失败留下，通过才删。`provenance` 不碰它——流程走完但验证红，同样该留下标记。
- **标记写在 `vp create` 成功之后**，不是 `bootstrap` 的第一行：`vp create` 拒绝非空目录，早写会让指南死在它自己的第一个写文件步骤上（实测：9 条 profile 全部以 `Target directory … is not empty` 失败，见 Considered Options）。代价是：若失败发生在 `vp create` 内部，标记还没写下——那种情况下目录要么是空的，要么是工具留下的半成品，`preflight` 按「普通非空」处理，这可以接受。
- **`preflight` 认它，并分成三支**：空 → 继续；非空且带标记 → 点名「这是一次没走完的初始化，删掉整个目录重来」，并原样打印标记内容；非空且无标记 → 保持原来的「把文件挪走」消息。两条消息都要被 E2E 断言，否则它们会悄悄合成一条。
- **不提供续跑，也不放宽 preflight。** 多数步骤不可重入（`rm -rf` 的破坏性、`vp create` 与 preflight 都要求空目录、`adr-land` 拒绝覆盖），而要续跑就必须判定「跑到哪了」——那是一条会漂移的推断规则；「stop, don't repair」这条纪律也不该被绕开。
- **不做「到哪一步了」的只读诊断**：更可靠的做法已经存在——跑验证段，它会点名缺什么；拒绝消息里指向它。

## Considered Options

- **把标记写在 `bootstrap` 的第一行**（脚手架之前）：拒绝——实测 9 条 profile 全挂在 `vp create`：`Target directory … is not empty`。标记必须在脚手架建成之后写。
- **只改文字**（在 README 与索引里写「失败就删掉重来」）：拒绝——文字在目录之外，而「这个目录没完成」是目录自己的事实；下一个读到它的人不会先去翻指南。
- **完整的续跑**（逐步记录进度、允许原地继续）：拒绝——见上；这是另一个决策，且要求每个步骤可重入。
- **放宽 preflight，接受「本指南的产物」**（白名单）：拒绝——「哪些文件属于本指南」是一份会漂移的清单；一个明确的标记文件是一条不会漂移的事实。
- **把标记放进 `.vite-plus-*` 命名空间**：拒绝——那正是「成功后不得残留」断言盯着的命名空间，而且它会被当成 scratch；标记不是 scratch，它是项目的自我陈述。
- **把标记写进 `docs/provenance.md`**：拒绝——出生证明是「跑完了」的产物，不能同时承担「没跑完」的陈述。

## Consequences

- `bootstrap` 在脚手架建成、断言通过之后写下标记；此后任何一步失败（包括验证段本身）都会把它留在原地。`vp create` 本身失败时还没有标记——那是唯一一个「失败却不自证」的窗口，接受它，因为标记不能早于脚手架存在。
- `assert.mjs` 断言成功的产物没有标记（`the finished project says it is finished`）；`run.sh` 新增负向控制「带标记的目录被 preflight 当成半成品拒绝、且不写任何文件」，并让原有的「普通非空」控制断言它**不会**打印半成品消息。
- 标记存在时唯一被支持的做法是删掉目录重来；指南的 `README.md` 与索引都这么写。
- 失败后想确认缺什么，仍然可以跑验证段：它今天就会给出具体的缺失项。
